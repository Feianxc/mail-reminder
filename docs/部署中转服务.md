# 中转服务部署

Windows、安卓和 iOS 通过相同团队与网段加入一个房间。桌面局域网通信使用 UDP，手机同步使用中转服务的 HTTPS 接口。

## 启动服务

准备 Node.js 22 或更新版本。服务仅使用 Node 自带模块。

在仓库根目录运行以下示例，将域名替换为自己的 HTTPS 域名。

```bash
HOST=127.0.0.1 \
PORT=45822 \
BASE_PATH=/mail-reminder \
PUBLIC_URL=https://relay.example.com/mail-reminder/ \
MAIL_DATA_DIR=/var/lib/mail-reminder \
node server/server.mjs
```

`MAIL_DATA_DIR` 需要由运行服务的系统用户写入。手机绑定和团队信息保存在该目录的 `state.json`，更新部署时继续使用原数据目录。

在 HTTPS 反向代理中，将 `/mail-reminder/` 转发到 `http://127.0.0.1:45822`，保留路径前缀。长轮询最长等待约二十五秒，反向代理超时需覆盖这一等待时间。

健康接口为 `GET /mail-reminder/api/health`。接口和客户端请求使用产品 User-Agent，格式见 [协议说明](../server/PROTOCOL.md)。

## 客户端地址

桌面端在生成后的 `team.json` 中设置 `RelayUrl`，例如 `https://relay.example.com/mail-reminder/`。

安卓端需要同步替换以下位置。

- `android/src/online/feian/mailreminder/SecurityPolicy.java` 的服务 URL 与更新来源校验。

iOS 端需要同步替换以下位置。

- `ios/MailReminder/Models.swift` 的 `MailConstants.baseURL`。
- `ios/MailReminder/APIClient.swift` 中请求主机与路径的同源校验。

服务端的 `PUBLIC_URL` 与客户端地址保持一致。修改后重新构建客户端，使用桌面生成的绑定码加入自己的团队。

## Linux 常驻运行

`server/mail-reminder.service` 是 systemd 服务示例。部署时按实际安装目录调整 `WorkingDirectory`、`ExecStart` 和环境变量，并准备专用运行用户与数据目录。

运行用户需要读取程序目录和可选下载目录，并写入 `MAIL_DATA_DIR`。示例将服务绑定到本机回环地址，由 HTTPS 反向代理提供公开入口。

## 在线更新

`RELEASES_DIR` 可指定存放公开应用文件的目录。当前服务端代码识别 Windows 1.3.0 ZIP 和安卓 1.3.0 APK，文件名与版本映射见 `server/relay.mjs` 中的 `releases` 以及更新清单响应。发布新版本时需同步调整映射和清单版本字段。

Windows 公共更新 ZIP 包含 EXE、运行配置和使用说明三个应用文件。团队配置通过团队内部渠道分发，客户端升级时沿用本机 `team.json`。

当前安卓源码为1.3.1，配套服务端的内置下载映射仍为1.3.0。使用在线更新分发1.3.1时，部署者需先更新服务端映射与版本信息。

iOS 的本地签名安装流程见 [安装教程](../ios/安装与使用教程.txt)。当前 iOS 版在前台接收提醒，后台和锁屏接收需要后续 APNs 接入。
