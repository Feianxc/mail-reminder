本项目包含 Windows 1.3.0、安卓 1.3.1、iOS 1.3.0 和 Node.js 中转服务。

以下记录区分编译、主机检查、接口联调与真实设备。`pass` 表示相应范围已通过，`not run` 表示该项尚未执行，整体真实业务验收为 `partial`。

| 范围 | 状态 | 现有证据 |
| --- | --- | --- |
| Windows 通信 | pass | 63项，含中文改名、回执、LAN与中转去重、旧客户端桥接 |
| Windows 更新器 | pass | 48项隔离样本，含包校验、配置保留、并发锁与部分替换回滚 |
| Windows 主题与界面 | pass | 8项资源布局、192项WPF入口与窗口、13项旧配置本机启动检查 |

| 安卓 1.3.1 | pass | APK构建、验签、对齐、包回读，以及18项安全和26项并发主机检查 |
| 服务端 | pass | 15组HTTP回归，含0/1/N集合、房间隔离、绑定持久化、双等待连接唤醒 |

## 移动端延迟

原安卓接收与回执串行执行。主机受控测试让两条回执响应分别等待十五秒，串行收取出现约29.9秒延迟，独立收取约9.5毫秒。

安卓1.3.1使用生产 `RelayWorkers` 和 `ReceiptQueue` 进行独立HTTP检查，回执响应被挂起时，新提醒仍在约73毫秒到达接收线程。该结果限于本地主机测试。历史公网接口样本约一秒。

复现工具可用以下命令运行。

```bash
node tools/latency-ack-fault.mjs
```

实际手机的收发延迟还取决于网络、后台状态和通知权限。安卓客户端会显示全局通知权限与提醒频道关闭状态。

## 使用范围

iOS 当前采用前台长轮询，接收范围为应用保持前台且屏幕解锁。后台和锁屏推送尚待原生APNs接入。

软件收到与人工知晓分别统计，五秒自动关闭仅结束提醒展示。用户点击“知道了”才提交人工知晓回执。
